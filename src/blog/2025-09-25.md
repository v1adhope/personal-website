Golang is a messy language. It's a poor fit for rich domain models.

- No ability to lock dependencies when updating them all with `go get -u`. You can't keep specific ones pinned during that update.
- No built-in option types. Use references or implement a lot of boilerplate yourself.
- Poor package and scope design.
  - Why is your package called `httpserverv2`? This naming convention is common and often unreadable.
  - How do you organize a lot of code in one package? No way. Suffer.
- No official project layout. People usually put code wherever they want.
- No built-in constructors or even static methods. Common function names like `MySuperCumbersomeStructModelToRequest` aren't bound to a type.
- No shorthand for returning zero values or handling `err != nil`.
- Simplicity isn't always a virtue. Here, it's a lack of features.
